# App Flow Document for the Corporate Finance Tracker

## Onboarding and Sign-In/Sign-Up
A new user lands on the finance tracker’s homepage, which introduces the application’s main benefits and invites them to either sign in or sign up. When the user clicks the sign-up call to action, they are taken to a form that requests an email address and a password, along with a password confirmation. After submitting, the app calls Supabase Auth to create an account and, if email confirmation is enabled, instructs the user to check their inbox. Once the account is confirmed, the user is redirected automatically to the main dashboard.

If the user already has an account, they can click the sign-in link to reach a login form where they enter their email and password. On successful authentication, they arrive at the dashboard. If the credentials are invalid, an inline error message appears above the form fields. The sign-in form also offers a "Forgot Password" link. Clicking that takes the user to a password recovery page where they provide their email. The app then sends a reset link via Supabase and displays a confirmation message prompting the user to check their email. After resetting the password, the user can sign in with the new credentials. Throughout all these pages, a link in the header or footer allows the user to return to the landing page.

## Main Dashboard or Home Page
After signing in, the user sees the main dashboard, which is divided into a sidebar on the left and a content area on the right. The sidebar always shows navigation links labeled Dashboard, Income, Expenses, Reports, and Settings. Above the sidebar, the app logo appears. On the right, the header includes the user’s avatar and name; clicking the avatar opens a dropdown menu with options to visit Settings or Sign Out.

In the dashboard’s content area, the user first encounters summary cards that display total income, total expenses, and net profit for the current period. Below those cards, a table lists the most recent transactions, mixing both incomes and expenses. Above this table, two prominent buttons allow the user to quickly add either an income or an expense. Every element is clickable, guiding the user to more detailed views or actions.

## Detailed Feature Flows and Page Transitions
When the user wants to record a new expense, they click the "Add Expense" button on the dashboard or any income/expense page. This action opens a modal dialog containing a form with fields for amount, date, category, and description. React Hook Form manages the form state while Zod validates each field in real time. If the user tries to type letters in the amount field or skips a required field, an inline validation message appears. Once the user submits valid data, the form calls Supabase to insert the new transaction record. TanStack Query automatically triggers a refetch of the transaction list across all pages, causing the dashboard table and related tables to update instantly. A toast notification briefly appears at the top of the screen to confirm that the expense was recorded successfully.

The flow for adding income is identical, except the form sets a different transaction type. To view all incomes or all expenses, the user clicks the respective link in the sidebar. This navigates to a page with a table filtered by that type. On the table page, date-range pickers and category dropdowns allow the user to refine the list; selecting filter criteria and clicking an "Apply" button refreshes the table with TanStack Query.

Editing a transaction begins when the user clicks the edit icon on any row in the transaction table. That action opens the same modal form, pre-populated with the existing data. After making changes, the user submits the form, Supabase updates the record, and TanStack Query refreshes the data. Deleting a transaction works by clicking the trash icon in the table row, which triggers a confirmation dialog. Confirming the deletion calls Supabase to remove the record, refetches the list, and shows a toast.

To generate detailed analytics, the user visits the Reports page from the sidebar. This page displays date-range inputs at the top and a chart area below. Once the user selects a start and end date and applies the filter, TanStack Query fetches aggregated income and expense totals from Supabase. The page then renders interactive charts showing trends over time, such as weekly or monthly breakdowns. Hovering over chart points reveals specific values.

For organizations that enable role-based access control, users with the Admin role see an extra section under Settings labeled User Management. There, an admin can see a list of all registered employees, change their roles, and deactivate or reactivate accounts. Admins also see every transaction in the system regardless of who created it. Regular employees only see their own records.

## Settings and Account Management
Clicking Settings in the sidebar navigates to the user’s account page, which is organized into tabs. The Profile tab shows editable fields for name and email. The user can update these fields and save changes, which calls Supabase to update the user record and displays a toast on success. The Password tab offers a form to change the current password by entering the old password, the new password, and a confirmation. Upon submission, the app updates the credentials via Supabase and notifies the user of success or failure.

If role-based features are enabled, an Admin tab appears, showing user management tools. Otherwise, notification preferences are shown, allowing the user to toggle email or in-app notifications for certain events. At the bottom of Settings, a Sign Out button logs the user out of Supabase and redirects them to the landing page. A persistent link in the header also allows signing out from any view.

## Error States and Alternate Paths
Whenever the user submits a form with invalid data, inline validation errors appear directly under the offending fields. If the user’s network connection drops or Supabase returns an error during a create, update, or delete operation, a toast notification appears describing the failure and offering a retry option. In cases where the user attempts to access a restricted page—such as the Admin panel without sufficient permissions—a 403-style screen appears explaining that they are not authorized and provides a button to return to the dashboard.

On sign-in or sign-up pages, if the user enters incorrect credentials or tries to register with an email that already exists, a clear error message appears above the form. If a password reset link has expired, the forgot password page shows a message telling the user that the link is invalid and invites them to request a new reset link. Throughout these flows, the user can always navigate back to the main sign-in or landing page.

## Conclusion and Overall App Journey
From the moment a new user arrives at the landing page to the daily tasks of logging income or expenses, this application guides them through a consistent and intuitive path. Users create an account, verify their email if necessary, and enter the dashboard where they immediately see key financial metrics. With simple dialogs, they record transactions that update in real time. They can drill into lists of incomes or expenses, generate interactive reports, and manage their own account settings. Admins gain extra control to oversee user roles and access all data. At any point they can sign out and return later, confident that their data remains accurate and secure. This flow ensures that tracking corporate finances is straightforward and reliable from start to finish.
